## 一、I/O 子系统概述 {#一-i-o-子系统概述}


### 1.1 什么是 I/O {#1-dot-1-什么是-i-o}

**I/O（输入/输出）** 是计算机与外部设备之间交换信息的过程：

-   **输入** ：键盘输入、磁盘读、网络收包
-   **输出** ：显示器输出、磁盘写、网络发包


### 1.2 I/O 系统层次结构 {#1-dot-2-i-o-系统层次结构}

```mermaid
flowchart TB
    A["用户程序<br/>printf / fread / socket"]
    B["用户空间 I/O 软件<br/>C 标准库、系统调用封装"]
    C["设备无关 I/O 层<br/>文件系统、VFS、协议栈"]
    D["设备驱动程序<br/>与具体设备交互"]
    E["中断服务程序<br/>处理设备中断"]
    F["I/O 硬件<br/>设备控制器、外部设备"]

    A --> B --> C --> D --> E --> F
```


### 1.3 三种 I/O 控制方式 {#1-dot-3-三种-i-o-控制方式}

```mermaid
flowchart LR
    subgraph 查询["程序查询方式"]
        Q1["CPU 轮询设备状态"] --> Q2["等待就绪"]
    end
    subgraph 中断["中断驱动方式"]
        I1["CPU 做自己的事"] --> I2["设备就绪 → 发中断"]
        I2 --> I3["CPU 响应中断处理"]
    end
    subgraph DMA["DMA 方式"]
        D1["CPU 设置 DMA 参数"] --> D2["DMA 直接传数据"]

    end
```

| 方式 | CPU 干预    | 适用场景 |
|----|-----------|------|
| 程序查询 | 最多（轮询等待） | 简单、低速设备 |
| 中断驱动 | 中等（中断时处理） | 中速设备 |
| DMA  | 最少（仅初始化和完成） | 高速大块数据传输 |

## 二、用户空间 I/O 软件 {#二-用户空间-i-o-软件}


### 2.1 系统级 I/O vs 标准 I/O {#2-dot-1-系统级-i-o-vs-标准-i-o}

```mermaid
flowchart TD
    A["应用程序"] --> B["标准 I/O 库<br/>printf / fread / fwrite"]
    B --> C{"用户缓冲区<br/>是否满/刷新?"}
    C -->|否| B
    C -->|是| D["系统调用<br/>read / write"]
    D --> E["内核"]
    E --> F["设备驱动 → 硬件"]
```

| 类型    | 函数                                | 缓冲  | 系统调用次数 |
|-------|-----------------------------------|-----|--------|
| 系统级 I/O | `open` / `read` / `write` / `close` | 无缓冲 | 每次调用一次 |
| 标准 I/O | `fopen` / `fread` / `fwrite`        | 用户态缓冲 | 缓冲满才调用 |


### 2.2 文件描述符 {#2-dot-2-文件描述符}

在 Unix/Linux 中， **一切皆文件** ：普通文件、目录、设备、管道、Socket、符号链接。

进程启动时默认打开三个文件描述符：

| 描述符 | 名称         | 流向    |
|-----|------------|-------|
| 0   | stdin（标准输入） | 键盘 → 程序 |
| 1   | stdout（标准输出） | 程序 → 屏幕 |
| 2   | stderr（标准错误） | 程序 → 屏幕 |


### 2.3 标准 I/O 的缓冲类型 {#2-dot-3-标准-i-o-的缓冲类型}

| 缓冲类型 | 触发条件     | 示例      |
|------|----------|---------|
| 全缓冲 | 缓冲区满才实际 I/O | 普通文件  |
| 行缓冲 | 遇到换行符才实际 I/O | 终端 stdout |
| 无缓冲 | 每次都实际 I/O | stderr    |

### 3.2 设备分类与驱动 {#3-dot-2-设备分类与驱动}

| 类型 | 访问方式 | 示例     |
|----|------|--------|
| 字符设备 | 按字节流顺序访问 | 键盘、串口、终端 |
| 块设备 | 按块随机访问 | 磁盘、SSD |
| 网络设备 | 面向数据包 | 网卡     |

**驱动加载方式** ：

-   静态编译进内核
-   动态加载（ `.ko` 模块）： `insmod` / `modprobe`


### 3.3 中断上半部与下半部 {#3-dot-3-中断上半部与下半部}

```mermaid
flowchart LR
    subgraph 上半部["上半部（Top Half）"]
        A1["关中断"] --> A2["快速应答设备"]
        A2 --> A3["读取关键数据"]
    end
    subgraph 下半部["下半部（Bottom Half）"]
        B1["开中断"] --> B2["处理协议逻辑"]
        B2 --> B3["唤醒等待进程"]
    end
    上半部 -->|立即执行| 下半部

```

| 机制            | 特点    |
|---------------|-------|
| 软中断（softirq） | 可并发，性能高 |
| tasklet         | 串行执行，简单 |
| 工作队列（workqueue） | 可睡眠，最灵活 |

## 五、现代技术扩展 {#五-现代技术扩展}


### 5.1 io_uring：新一代异步 I/O {#5-dot-1-io-uring-新一代异步-i-o}

```mermaid
flowchart LR
    subgraph 用户态["用户态"]
        SQ["提交队列 SQ"]
        CQ["完成队列 CQ"]
    end
    subgraph 内核态["内核态"]
        Engine["io_uring 内核引擎"]
    end
    SQ -->|提交请求| Engine
    Engine -->|完成事件| CQ
    SQ -.->|mmap 共享| Engine
    CQ -.->|mmap 共享| Engine
```

-   Linux 5.1+ 引入，两个共享环形缓冲区
-   **无需系统调用** 即可提交 I/O（mmap 共享）
-   支持文件、网络、定时器等所有 I/O 类型
-   性能远超 epoll + 线程池


### 5.2 零拷贝技术 {#5-dot-2-零拷贝技术}

```mermaid
flowchart LR
    subgraph 传统["传统 read+write"]
        direction LR
        D1["磁盘"] --> K1["内核缓冲区"]
        K1 --> U1["用户缓冲区"]
        U1 --> S1["Socket 缓冲区"]
        S1 --> N1["网卡"]
    end
    subgraph 零拷贝["sendfile 零拷贝"]
        direction LR
        D2["磁盘"] --> K2["内核缓冲区"]
        K2 --> S2["Socket 缓冲区"]
        S2 --> N2["网卡 DMA"]
    end
```

| 技术       | 原理              |
|----------|-----------------|
| `mmap`     | 文件映射到用户空间，减少一次拷贝 |
| `sendfile` | 内核内直接从文件传到 socket |
| `splice`   | 两个 fd 间零拷贝数据移动 |
| DMA        | 网卡直接从内存取数据 |


### 5.3 高性能网络 I/O {#5-dot-3-高性能网络-i-o}

```mermaid
flowchart TB
    subgraph 传统["传统网络栈"]
        A1["网卡"] --> A2["内核协议栈"]
        A2 --> A3["系统调用"]
        A3 --> A4["应用"]
    end
    subgraph DPDK["DPDK 用户态驱动"]
        B1["网卡"] --> B2["PMD 轮询<br/>绕过内核"]
        B2 --> B3["用户态应用"]
    end
```

-   **DPDK** ：绕过内核协议栈，用户态直接驱动网卡，PMD 轮询模式
-   **RDMA** ：远程直接内存访问，零内核参与，超低延迟
-   **XDP** ：在网卡驱动层（协议栈前）运行 eBPF 程序，极速包处理


### 5.4 eBPF：内核可编程 {#5-dot-4-ebpf-内核可编程}

-   不修改内核代码、不加载内核模块，即可在内核运行沙箱程序
-   应用：网络过滤、性能分析、安全监控、可观测性
-   工具：bpftrace、BCC、Cilium


### 5.5 NVMe 与现代存储 {#5-dot-5-nvme-与现代存储}

```mermaid
flowchart LR
    subgraph SATA["SATA SSD"]
        S1["单队列"]
        S2["深度 ~32"]
    end
    subgraph NVMe["NVMe SSD"]
        N1["65535 队列"]
        N2["每队列 65535 命令"]
        N3["PCIe 通道"]
    end
```

-   **NVMe** ：基于 PCIe，多队列并行，延迟远低于 SATA
-   **NVMe-oF** ：通过网络（RoCE/TCP）访问远程 NVMe
-   **IO 调度器** ：SSD 用 NOOP/NONE，HDD 用 Deadline/CFQ


### 5.6 设备虚拟化 {#5-dot-6-设备虚拟化}

| 方案            | 原理              | 性能 |
|---------------|-----------------|----|
| 全虚拟化        | QEMU 模拟设备     | 慢   |
| 半虚拟化（virtio） | Guest 用 virtio 驱动 | 中   |
| 直通（Passthrough） | 物理设备分给 VM   | 接近原生 |
| SR-IOV          | 一个物理设备虚拟多个 VF | 接近原生 |

### 简答题要点 {#简答题要点}

1.  查询：CPU 轮询，利用率低；中断：设备就绪发中断，利用率较高；DMA：控制器直接传输，CPU 干预最少。
2.  系统 I/O 无缓冲，每次系统调用；标准 I/O 用户态缓冲，减少系统调用次数。
3.  MMIO 将设备寄存器映射到内存地址空间，用访存指令；独立编址用专用 in/out 指令。
4.  上半部关中断快速处理紧急事，下半部开中断延迟处理非急事，减少关中断时间。
5.  减少数据在内存中的拷贝。sendfile：内核内文件直接到 socket；mmap：文件映射到用户空间。
