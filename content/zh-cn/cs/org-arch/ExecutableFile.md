## 一、可执行文件生成概述 {#一-可执行文件生成概述}


### 1.1 从源程序到可执行文件的完整流程 {#1-dot-1-从源程序到可执行文件的完整流程}

一个C语言源程序（~.c~）要经过以下四个阶段才能变成可执行文件：

```text
源程序(.c) → 预处理 → 编译 → 汇编 → 链接 → 可执行文件
```

| 阶段    | 输入         | 输出      | 主要工作                 |
|-------|------------|---------|----------------------|
| **预处理** | `.c` 源文件  | `.i` 中间文件 | 宏展开、头文件包含、条件编译处理、删除注释 |
| **编译** | `.i` 中间文件 | `.s` 汇编文件 | 词法分析、语法分析、语义分析、优化、生成汇编代码 |
| **汇编** | `.s` 汇编文件 | `.o` 目标文件 | 将汇编指令翻译为机器指令，生成可重定位目标文件 |
| **链接** | 多个 `.o` +库文件 | 可执行文件 | 符号解析、重定位、合并段 |


### 1.2 预处理阶段（Preprocessing） {#1-dot-2-预处理阶段-preprocessing}

-   **宏定义展开** ： `#define MAX 100` → 文本替换

-   **头文件包含** ： `#include <stdio.h>` → 插入头文件内容

-   **条件编译** ： `#ifdef`  / `#ifndef` / `#endif` 选择性保留代码

-   **删除注释** ：去除 `//` 和 `/**/` 注释

> GCC命令：

```bash
gcc -E hello.c -o hello.i
```


### 1.3 编译阶段（Compilation） {#1-dot-3-编译阶段-compilation}

编译器将C代码翻译为汇编代码，主要步骤：

1.  **词法分析** ：将字符流分解为token（关键字、标识符、常量等）
2.  **语法分析** ：生成抽象语法树（AST）
3.  **语义分析** ：类型检查、作用域分析
4.  **中间代码生成** ：生成三地址码或IR
5.  **代码优化** ：常量折叠、死代码消除、循环优化等
6.  **目标代码生成** ：生成对应架构的汇编代码

GCC命令：

```bash
gcc -S hello.i -o hello.s
```


### 1.4 汇编阶段（Assembly） {#1-dot-4-汇编阶段-assembly}

汇编器（as）将汇编指令逐条翻译为机器指令：

-   每条汇编指令对应一条机器指令
-   生成\*可重定位目标文件\*（ `.o` / `.obj` ）
-   目标文件中包含：代码段（ `.text` ）、数据段（ `.data` ）、BSS段（ `.bss` ）、符号表、重定位表等

GCC命令：

```bash
gcc -c hello.s -o hello.o
```


### 1.5 链接阶段（Linking） {#1-dot-5-链接阶段-linking}

链接器（ld）将多个目标文件和库文件合并为一个可执行文件：

-   **符号解析** ：将符号引用与符号定义关联起来
-   **重定位** ：将相对地址转换为绝对地址
-   **段合并** ：将多个目标文件的同类段合并


## 二、目标文件格式 {#二-目标文件格式}


### 2.1 ELF目标文件格式概述 {#2-dot-1-elf目标文件格式概述}

**ELF（Executable and Linkable Format）** 是Unix/Linux系统下的标准目标文件格式，支持三种类型：

| 类型         | 说明                      | 示例        |
|------------|-------------------------|-----------|
| **可重定位目标文件** | 由汇编器生成，包含代码和数据，可与其他目标文件链接 | `.o` 文件   |
| **可执行目标文件** | 由链接器生成，可直接加载执行 | `/bin/bash` |
| **共享目标文件** | 动态链接库，运行时加载    | `.so` 文件  |


### 2.2 ELF文件的整体结构 {#2-dot-2-elf文件的整体结构}

```text
┌─────────────────────────┐
│ ELF Header (ELF头)      │ ← 文件类型、架构、入口点等
├─────────────────────────┤
│ Program Header Table    │ ← 可执行文件需要，描述段信息
│ (程序头表)              │
├─────────────────────────┤
│ .text段 (代码段)        │ ← 机器指令
├─────────────────────────┤
│ .rodata段 (只读数据)    │ ← 字符串常量、const变量
├─────────────────────────┤
│ .data段 (已初始化数据)  │ ← 已初始化的全局/静态变量
├─────────────────────────┤
│ .bss段 (未初始化数据)   │ ← 未初始化的全局/静态变量（不占文件空间）
├─────────────────────────┤
│ .symtab (符号表)        │ ← 函数和全局变量信息
├─────────────────────────┤
│ .rel.text/.rel.data     │ ← 重定位条目
├─────────────────────────┤
│ .strtab (字符串表)      │ ← 符号名、段名等字符串
├─────────────────────────┤
│ Section Header Table    │ ← 描述各段的位置和大小
│ (节头表)                │
└─────────────────────────┘
```


### 2.3 可重定位目标文件格式 {#2-dot-3-可重定位目标文件格式}

关键段说明：

-   `.text` ：程序的机器代码

-   `.rodata` ：只读数据，如 `printf` 的格式字符串

-   `.data` ：已初始化的全局变量和静态变量

-   `.bss` ：未初始化的全局变量和静态变量，\*在文件中不占空间\*，仅记录大小

-   `.symtab` ：符号表，记录定义和引用的函数、全局变量

-   `.rel.text` ：代码段的重定位信息

-   `.rel.data` ：数据段的重定位信息

-   `.strtab` ：字符串表，存储符号名等字符串


### 2.4 可执行目标文件格式 {#2-dot-4-可执行目标文件格式}

与可重定位目标文件的区别：

-   增加了 **程序头表（Program Header Table）** ，描述加载到内存时的段映射
-   有明确的\*入口点地址\*（~e_entry~），即 `_start` 函数地址
-   重定位信息已被处理（静态链接后不再需要）
-   各段已分配最终的虚拟地址


### 2.5 可执行文件的存储器映像 {#2-dot-5-可执行文件的存储器映像}

加载到内存后，典型的进程地址空间布局（从低地址到高地址）：

\#+begin_examplenn
高地址 ┌─────────────────────────┐
       │ 内核空间 (Kernel)       │ ← 操作系统保留
       ├─────────────────────────┤
       │ 栈 (Stack)              │ ← 向下增长，局部变量、返回地址
       │                         │
       │ ...空闲...              │
       │                         │
       │ 堆 (Heap)               │ ← 向上增长，动态分配(malloc)
       ├─────────────────────────┤
       │ 未初始化数据 (.bss)     │ ← 未初始化全局变量
       ├─────────────────────────┤
       │ 已初始化数据 (.data)    │ ← 已初始化全局变量
       ├─────────────────────────┤
       │ 只读数据 (.rodata)      │ ← 字符串常量
       ├─────────────────────────┤
       │ 代码段 (.text)          │ ← 程序指令
低地址 └─────────────────────────┘
\#+end_example


## 三、符号解析与重定位 {#三-符号解析与重定位}


### 3.1 符号和符号表 {#3-dot-1-符号和符号表}


#### 符号的分类 {#符号的分类}

| 符号类型 | 说明           | 示例                         |
|------|--------------|----------------------------|
| **全局符号** | 本文件定义，可被其他文件引用 | 非static的函数、全局变量     |
| **外部符号** | 本文件引用，其他文件定义 | `extern` 声明的变量/函数     |
| **局部符号** | 仅本文件可见   | `static` 函数/变量、局部变量（通常不入符号表） |


#### 符号表条目（Elf32_Sym） {#符号表条目-elf32-sym}

```c
typedef struct {
    int st_name;   // 符号名在字符串表中的偏移
    int st_value;  // 符号的地址/偏移
    int st_size;   // 符号大小（字节）
    char st_info;  // 类型和绑定属性
    char st_other; // 保留
    short st_shndx;// 所在段的索引
} Elf32_Sym;
```


### 3.2 符号解析和静态链接 {#3-dot-2-符号解析和静态链接}


#### 符号解析规则 {#符号解析规则}

-   每个符号引用必须恰好对应一个符号定义
-   **强符号** ：函数定义、已初始化的全局变量
-   **弱符号** ：未初始化的全局变量
-   链接规则：
    1.  不允许有多个同名强符号
    2.  一个强符号和多个弱符号同名时，选择强符号
    3.  多个弱符号同名时，任选一个


#### 静态链接库（ `.a` 归档文件） {#静态链接库-dot-a-归档文件}

-   归档文件是多个目标文件的集合
-   链接器扫描归档文件时，只提取 **解析了未定义符号** 的目标文件
-   链接顺序很重要：库通常放在命令行最后


### 3.3 重定位过程 {#3-dot-3-重定位过程}

重定位分为两步：


#### 第一步：重定位节和符号定义 {#第一步-重定位节和符号定义}

-   链接器将所有同类节合并
-   为每个节分配运行时地址
-   为每个符号定义分配运行时地址


#### 第二步：重定位节中的符号引用 {#第二步-重定位节中的符号引用}

链接器修改代码段和数据段中对符号的引用，使其指向正确的运行时地址。

典型的重定位条目：

| 重定位类型   | 说明                   |
|---------|----------------------|
| `R_386_32`   | 绝对地址重定位，用于数据引用 |
| `R_386_PC32` | 相对地址重定位，用于函数调用（~call~） |

重定位公式（以 `R_386_PC32` 为例）：

```text
refaddr = S + A - P

其中：S = 符号的运行时地址
      A = 加数（指令中已有的偏移）
      P = 被重定位位置的运行时地址
```


### 3.4 动态链接 {#3-dot-4-动态链接}


#### 为什么需要动态链接？ {#为什么需要动态链接}

-   静态链接会将库代码复制到每个可执行文件中，浪费磁盘和内存
-   库更新时需要重新链接所有程序
-   动态链接库（ `.so` / `.dll` ）在运行时加载，多个进程共享一份


#### 动态链接的工作方式 {#动态链接的工作方式}

1.  **编译时** ：链接器只记录需要哪些动态库和符号，不复制代码
2.  **加载时** ：动态链接器（ `ld-linux.so` ）加载所需的共享库
3.  **运行时** ：通过 **过程链接表（PLT）** 和 **全局偏移表（GOT）** 实现延迟绑定


#### PLT（过程链接表）和GOT（全局偏移表） {#plt-过程链接表-和got-全局偏移表}

-   **GOT** ：数据段中的一个数组，每个条目保存一个函数的绝对地址
-   **PLT** ：代码段中的一个数组，每个条目是一段小代码，通过GOT间接调用函数
-   **延迟绑定（Lazy Binding）** ：函数第一次调用时才解析地址，后续调用直接跳转


## 四、可执行文件的加载 {#四-可执行文件的加载}


### 4.1 程序和进程的概念 {#4-dot-1-程序和进程的概念}

| 概念            | 说明                        |
|---------------|---------------------------|
| **程序（Program）** | 存储在磁盘上的可执行文件，是静态的指令和数据集合 |
| **进程（Process）** | 程序的一次执行过程，是动态的，拥有独立的地址空间和资源 |

一个程序可以对应多个进程（如同时运行多个 `bash` ）。


### 4.2 进程的虚拟地址空间 {#4-dot-2-进程的虚拟地址空间}

每个进程都有自己独立的\*虚拟地址空间\*，通过内存管理单元（MMU）映射到物理内存。

**虚拟地址空间的优点** ：

-   进程之间相互隔离，提高安全性
-   简化内存管理，每个进程看到统一的地址布局
-   允许使用比物理内存更大的地址空间（虚拟存储器）


### 4.3 execve函数和main函数 {#4-dot-3-execve函数和main函数}


#### execve系统调用 {#execve系统调用}

```c
int execve(const char *filename, char *const argv[], char *const envp[]);
```

-   加载并执行指定的可执行文件
-   替换当前进程的地址空间（不创建新进程）
-   成功时不返回，失败时返回-1


#### 程序启动流程 {#程序启动流程}

```text
shell调用fork()创建子进程
    ↓
子进程调用execve()加载可执行文件
    ↓
加载器映射代码段、数据段到虚拟地址空间
    ↓
设置栈，压入argc、argv、envp
    ↓
跳转到_start函数（C运行时启动代码）
    ↓
_start调用__libc_start_main
    ↓
调用main(argc, argv, envp)
    ↓
main返回后调用exit()
```


### 4.4 fork函数和程序的启动加载 {#4-dot-4-fork函数和程序的启动加载}


#### fork系统调用 {#fork系统调用}

```c
pid_t fork(void);
```

-   创建一个新进程（子进程）
-   子进程是父进程的 **副本** ，复制父进程的地址空间
-   **写时复制（Copy-on-Write, COW）** ：fork时不真正复制内存，只有当任一进程修改页面时才复制
-   返回值：父进程返回子进程PID，子进程返回0


#### fork+exec模式 {#fork-plus-exec模式}

Unix/Linux中启动新程序的标准模式：

```c
pid_t pid = fork();

if (pid == 0) {
    // 子进程：加载新程序
    execve("/bin/ls", argv, envp);
} else {
    // 父进程：等待子进程结束
    wait(NULL);
}
```


## 五、程序的执行和中央处理器 {#五-程序的执行和中央处理器}


### 5.1 程序及指令的执行过程 {#5-dot-1-程序及指令的执行过程}

一条指令的执行分为以下阶段（经典五级流水线）：

| 阶段     | 缩写                    | 主要工作            |
|--------|-----------------------|-----------------|
| **取指令** | IF (Instruction Fetch)  | 从内存取指令，PC自增 |
| **指令译码** | ID (Instruction Decode) | 解析操作码，读寄存器 |
| **执行** | EX (Execute)            | ALU计算地址/运算结果 |
| **访存** | MEM (Memory Access)     | 读写数据存储器（load/store） |
| **写回** | WB (Write Back)         | 将结果写回寄存器    |


### 5.2 CPU的基本功能和组成 {#5-dot-2-cpu的基本功能和组成}


#### CPU的基本功能 {#cpu的基本功能}

1.  **指令控制** ：控制指令的执行顺序
2.  **操作控制** ：产生每条指令所需的控制信号
3.  **时间控制** ：对操作信号进行定时控制
4.  **数据加工** ：进行算术和逻辑运算


#### CPU的基本组成 {#cpu的基本组成}

```text
┌─────────────────────────────────────────┐
│                CPU                      │
│  ┌──────────┐   ┌──────────────────┐    │
│  │  运算器  │   │      控制器      │    │
│  │  (ALU)   │   │      (CU)        │    │
│  │          │   │                  │    │
│  │ 通用寄存器│  │ 指令寄存器(IR)   │    │
│  │ 程序计数器│  │ 程序计数器(PC)   │    │
│  │  (PC)    │   │ 指令译码器(ID)   │    │
│  │ 状态寄存器│  │ 时序系统         │    │
│  │  (PSW)   │   │ 微操作信号发生器 │    │
│  └──────────┘   └──────────────────┘    │
└─────────────────────────────────────────┘
```

**关键寄存器** ：

-   **PC（程序计数器）** ：存放下一条指令的地址
-   **IR（指令寄存器）** ：存放当前正在执行的指令
-   **MAR（存储器地址寄存器）** ：访问内存时的地址
-   **MDR（存储器数据寄存器）** ：与内存交换的数据
-   **PSW（程序状态字）** ：保存条件标志（ZF、CF、OF、SF等）


### 5.3 打断程序正常执行的事件 {#5-dot-3-打断程序正常执行的事件}


#### 异常（Exception） {#异常-exception}

-   **内部异常** ：由CPU内部事件引起，与当前执行指令同步
-   分类：
    -   **故障（Fault）** ：可恢复，如缺页异常、除法错误
    -   **陷阱（Trap）** ：有意触发，如系统调用（ `int 0x80` / `syscall` ）
    -   **终止（Abort）** ：不可恢复，如硬件错误


#### 中断（Interrupt） {#中断-interrupt}

-   **外部中断** ：由CPU外部设备引起，与当前执行指令异步
-   如：定时器中断、键盘中断、磁盘I/O完成中断
-   **可屏蔽中断** ：通过IF标志位控制
-   **不可屏蔽中断（NMI）** ：如电源故障


### 5.4 异常和中断的响应过程 {#5-dot-4-异常和中断的响应过程}

1.  **保存现场** ：将当前PC（返回地址）和PSW压入栈
2.  **识别中断源** ：通过中断向量表找到对应的处理程序入口
3.  **切换到内核态** ：提高特权级
4.  **执行中断/异常处理程序**
5.  **恢复现场** ：从栈中弹出PC和PSW
6.  **返回被中断的程序** ： `iret` 指令


### 5.5 指令流水线的基本概念 {#5-dot-5-指令流水线的基本概念}


#### 流水线思想 {#流水线思想}

将指令执行过程拆分为多个阶段，多条指令\*重叠执行\*，提高吞吐量。

```text
时间→    1   2   3   4   5   6   7   8   9
指令1:   IF  ID  EX  MEM WB
指令2:       IF  ID  EX  MEM WB
指令3:           IF  ID  EX  MEM WB
指令4:               IF  ID  EX  MEM WB
```


#### 流水线的性能指标 {#流水线的性能指标}

-   **吞吐量（Throughput）** ：单位时间内完成的指令数
-   **延迟（Latency）** ：单条指令从开始到完成的时间
-   理想情况下，五级流水线吞吐量提升约5倍


#### 流水线冒险（Hazard） {#流水线冒险-hazard}

| 冒险类型 | 原因                       | 解决方法                   |
|------|--------------------------|------------------------|
| **结构冒险** | 硬件资源冲突（如单端口存储器同时取指和访存） | 增加硬件资源、分离指令/数据Cache |
| **数据冒险** | 指令间存在数据依赖（如 `add` 后立即使用结果） | 流水线停顿（气泡）、数据转发（Forwarding） |
| **控制冒险** | 分支指令改变PC，导致预取指令无效 | 分支预测、延迟槽、提前计算分支地址 |


## 六、现代技术扩展 {#六-现代技术扩展}


### 6.1 现代编译器与构建系统 {#6-dot-1-现代编译器与构建系统}


#### LLVM与Clang {#llvm与clang}

-   **LLVM** ：模块化的编译器基础设施，提供可复用的编译组件
-   **Clang** ：基于LLVM的C/C++/Objective-C编译器前端
-   优势：更快的编译速度、更友好的错误信息、模块化设计
-   支持 **JIT（即时编译）** ：在运行时将中间代码编译为机器码

### 6.2 WebAssembly：跨平台的可执行格式 {#6-dot-2-webassembly-跨平台的可执行格式}

-   **Wasm** 是一种低级虚拟机指令格式，可在浏览器中高效运行
-   编译目标：C/C++/Rust → WebAssembly
-   特点：接近原生性能、沙箱安全、跨平台
-   应用：浏览器端高性能计算、游戏、插件系统、Serverless


### 6.3 容器与进程隔离 {#6-dot-3-容器与进程隔离}

-   **Docker容器** ：基于Linux Namespace和Cgroups的轻量级虚拟化
-   每个容器有独立的进程空间、网络、文件系统
-   与虚拟机相比，容器共享宿主内核，启动更快、开销更小
-   **OCI镜像格式** ：标准化的容器镜像格式，类似可执行文件的分发


### 6.4 现代CPU架构演进 {#6-dot-4-现代cpu架构演进}


#### 超标量与乱序执行 {#超标量与乱序执行}

-   **超标量（Superscalar）** ：一个周期发射多条指令
-   **乱序执行（Out-of-Order, OoO）** ：指令按数据可用性而非程序顺序执行
-   **重排序缓冲区（ROB）** ：保证按程序顺序提交结果


#### 分支预测 {#分支预测}

-   **动态分支预测** ：基于历史记录预测分支方向
-   **TAGE预测器** ：现代CPU使用的高精度预测器
-   **推测执行** ：预测后提前执行指令，预测错误时回滚


#### 多核与多线程 {#多核与多线程}

-   **SMT（同时多线程）** ：一个物理核心模拟多个逻辑核心
-   Intel Hyper-Threading、AMD SMT
-   利用指令级并行（ILP）和线程级并行（TLP）


### 6.5 异常与中断的现代实现 {#6-dot-5-异常与中断的现代实现}

-   **APIC（高级可编程中断控制器）** ：支持多处理器中断路由
-   **MSI（消息信号中断）** ：通过写内存地址触发中断，替代传统引脚中断
-   **IO APIC** ：管理I/O设备的中断分发
-   **中断亲和性** ：将特定中断绑定到指定CPU核心

### 简答题要点 {#简答题要点}

1.  静态链接：编译时将库代码复制到可执行文件，文件大但运行不依赖库；动态链接：运行时加载共享库，文件小、可共享但需保证库存在。
2.  `.text` 存机器指令； `.data` 存已初始化全局/静态变量； `.bss` 存未初始化全局/静态变量（不占文件空间）； `.symtab` 存符号表信息。
3.  IF取指、ID译码读寄存器、EX执行运算、MEM访存、WB写回寄存器。
4.  结构冒险→增加硬件；数据冒险→转发/停顿；控制冒险→分支预测/延迟槽。
5.  异常是内部同步事件（缺页、除法错）；中断是外部异步事件（键盘、定时器）。
